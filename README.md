## 📖 О проекте

Репозиторий демонстрирует два фундаментально различных подхода к обработке данных: **пакетный ETL** и **потоковую обработку**. Часть 1 реализует полный ETL-пайплайн на Python с загрузкой данных из CSV, очисткой, агрегацией и сохранением в SQLite. Часть 2 разворачивает кластер Apache Kafka и реализует систему real-time обработки событий заказов.

# Технологии Программирования · Общее заключение

В ходе лабораторной работы №16 были последовательно реализованы и сопоставлены два принципиально различных подхода к обработке данных.

**Часть 1** продемонстрировала полный цикл ETL-пайплайна: исходный файл `sales.csv` объёмом 11 строк прошёл через три уровня качественной обработки (удаление 1 дубликата, заполнение пропусков строки 1004, удаление аномалии строки 1005), был агрегирован в 3 аналитические группы и загружен в базу `sales.db` в таблицы `sales_cleaned` и `sales_aggregated`. Пайплайн успешно завершился за ~1,3 секунды.

**Часть 2** показала архитектуру потоковой обработки: Kafka-кластер в Docker обеспечил инфраструктуру для публикации и потребления событий с задержкой в миллисекунды. По итогам обработки 20 заказов консюмер зафиксировал выручку **971 000,00 руб.** и средний чек **48 550,00 руб.** в режиме реального времени.

**Сравнительная таблица подходов:**

| Критерий | ETL + SQLite (Часть 1) | Apache Kafka (Часть 2) |
|---|---|---|
| Парадигма | Пакетная (batch) | Потоковая (streaming) |
| Источник данных | Статический CSV-файл | Непрерывный поток событий |
| Задержка результата | ~1–2 с (малый объём) | Миллисекунды после события |
| Инфраструктура | Python + pandas + SQLite | Docker + Zookeeper + Kafka |
| Порог сложности | Низкий | Высокий |
| Масштабируемость | Ограничена памятью процесса | Горизонтальная (партиции + брокеры) |
| Отказоустойчивость | Н/П (файловая обработка) | Репликация данных |
| Повторная обработка | Перезапуск скрипта | Сброс оффсета (`auto_offset_reset`) |
| Типичное применение | Ночные отчёты, DWH-загрузки | Fraud detection, мониторинг, рекомендации |

Обе технологии не являются конкурентами — они решают разные задачи. Зрелые аналитические платформы объединяют оба подхода: Kafka формирует «слой скорости» для оперативных решений, тогда как периодические ETL-пайплайны формируют «слой пакетной обработки» для долгосрочной аналитики.
